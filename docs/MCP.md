# MCP: агент, почта и встречи Aster Mail

MCP даёт локальному агенту доступ к запущенному Aster Mail: поиск и чтение
писем, список и создание папок, перенос писем, правила для новых входящих,
поиск и просмотр встреч, занятость, подбор общего времени, отправка писем,
ответы, пересылка, черновики, вложения, операции со встречами и настройки клиента.
Агент использует текущую сессию Aster; пароль Exchange ему не передаётся.

## Подключение

1. Запустите Aster Mail, откройте **Настройки (шестерёнка) → MCP · Агенты**
   и нажмите **Включить MCP**. В этом разделе есть инструкция и текущий статус. Доступ выключен по умолчанию и не сохраняется между запусками.
   При запуске из исходников можно использовать `npm start -- --mcp`.
2. Выберите **Claude Code / Desktop, Codex, DeepSeek Harness (dsh), Continue
   или Kilo Code**. Нажмите **Скопировать инструкцию для агента** и вставьте
   задачу из пяти строк в его чат. В ней уже есть настоящий путь, место
   настройки выбранного harness и проверка подключения без отправки писем.
   Для настройки вручную раскройте **Ручная настройка и конфигурация**
   и скопируйте конфигурацию выбранного harness.
   Требуется установленный Node.js 22 или новее;
   если агент не находит `node`, укажите полный путь к нему в `command`.
   Используется стандартный транспорт stdio, версия MCP 2025-11-25
   (также поддерживаются 2024-11-05, 2025-03-26 и 2025-06-18).
3. Подключитесь к Exchange в Aster Mail. Демо не предоставляет агенту
   вымышленные или настоящие письма. Перезапустите подключение MCP у агента,
   если его настройки требуют этого после добавления сервера.

Раздел также открывается через меню приложения **MCP → Как подключить агента · инструкция**.
В меню MCP остаются переключатель доступа и копирование конфигурации.

Конфигурация содержит `command: "node"` и абсолютный путь к `mcp-stdio.cjs`
в профиле Aster. Скрипт создаётся при включении MCP, работает и в установленном
приложении и не требует исходников. Не меняйте его путь на `app.asar`.

## Настройка популярных harness

В **Настройки → MCP · Агенты** выберите свой harness: Aster покажет его
инструкцию и готовую задачу для вставки в чат агента. Копируемая задача занимает пять строк
и включает настоящий абсолютный путь к скрипту. В примерах ниже `/ABSOLUTE/PATH/mcp-stdio.cjs` нужно заменить путём из
Aster. Сохраняйте существующие настройки и серверы при добавлении блока.
Если `node` не найден, замените его полным путём к Node.js. Aster и harness
должны работать на одном компьютере под тем же пользователем.

### Claude Code

Добавьте сервер в `.mcp.json` в корне проекта:

```json
{
  "mcpServers": {
    "aster-mail": {
      "type": "stdio",
      "command": "node",
      "args": ["/ABSOLUTE/PATH/mcp-stdio.cjs"]
    }
  }
}
```

Или зарегистрируйте его для своего пользователя через CLI:

```sh
claude mcp add --transport stdio --scope user aster-mail -- node "/ABSOLUTE/PATH/mcp-stdio.cjs"
```

Перезапустите Claude Code. Для проектного сервера подтвердите подключение;
статус доступен через `/mcp` или `claude mcp get aster-mail`.
[Официальная инструкция Claude Code](https://code.claude.com/docs/en/mcp).

### Claude Desktop

Откройте **Settings → Developer → Edit Config** и добавьте сервер в
`claude_desktop_config.json` под ключом `mcpServers`: `command: "node"`,
`args: ["/ABSOLUTE/PATH/mcp-stdio.cjs"]`. Можно взять полный JSON из Aster,
выбрав **Claude Desktop**. Полностью перезапустите Claude Desktop.
[Официальная инструкция локальных серверов MCP](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

### Codex: приложение, CLI и IDE

Добавьте в `~/.codex/config.toml`:

```toml
[mcp_servers.aster-mail]
command = "node"
args = ["/ABSOLUTE/PATH/mcp-stdio.cjs"]
```

Альтернатива для CLI:

```sh
codex mcp add aster-mail -- node "/ABSOLUTE/PATH/mcp-stdio.cjs"
```

Перезапустите подключение или Codex; `codex mcp list` показывает регистрацию.
[Официальная инструкция Codex](https://learn.chatgpt.com/docs/extend/mcp).

### DeepSeek Harness (dsh)

Добавьте запись в Cordis-конфигурацию нужного профиля:

```yaml
- id: mcp-aster-mail
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: aster-mail
    transport: stdio
    command: node
    args: ["/ABSOLUTE/PATH/mcp-stdio.cjs"]
```

Перезагрузите профиль. В Web/Desktop с MCP manager можно вместо этого
добавить сервер через Settings: имя `aster-mail`, транспорт `stdio`, команда
`node`, единственный аргумент — путь к скрипту Aster. Выберите один способ
подключения, чтобы не регистрировать одинаковый сервер дважды.
[Конфигурация dsh-mcp-client](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md),
[MCP manager](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-manager/README.md).

### Continue

Создайте `.continue/mcpServers/aster-mail.yaml` в проекте:

```yaml
name: Aster Mail
version: 1.0.0
schema: v1
mcpServers:
  - name: aster-mail
    command: node
    args: ["/ABSOLUTE/PATH/mcp-stdio.cjs"]
```

Перезагрузите Continue и включите **Agent mode**. Также Continue принимает
обычный `mcpServers` JSON в `.continue/mcpServers/aster-mail.json`.
[Официальная инструкция Continue](https://docs.continue.dev/customize/deep-dives/mcp).

### Kilo Code

В расширении откройте **Settings → MCP → Add Server → Local (stdio)**:
имя `aster-mail`, команда `node`, единственный аргумент — абсолютный путь к
`mcp-stdio.cjs` из Aster.

В текущем Kilo CLI добавьте в `~/.config/kilo/kilo.jsonc`:

```json
{
  "mcp": {
    "aster-mail": {
      "type": "local",
      "command": ["node", "/ABSOLUTE/PATH/mcp-stdio.cjs"]
    }
  }
}
```

В старых версиях с ключом `mcpServers` используйте формат **Другой harness · JSON**
из Aster. Проверьте, что сервер включён в списке MCP.
[Официальная инструкция Kilo Code](https://kilo.ai/docs/automate/mcp/using-in-kilo-code).

### Проверка подключения и частые ошибки

- Попросите агента: «Вызови `get_account` в Aster Mail и найди письма от anna@example.com».
- `connected: false`: подключите Exchange в Aster; демо-письма через MCP недоступны.
- Сервер недоступен: проверьте статус в **Настройки → MCP · Агенты** и включите MCP.
- `node` не найден: укажите полный путь к установленному Node.js 22+.
- Файл скрипта не найден: скопируйте конфигурацию из запущенного Aster; не используйте путь к `app.asar`.
- После обновления Aster переподключите MCP в harness, чтобы обновились инструменты.
- Запрос с неизвестным результатом отправки не повторяйте: сначала проверьте папку «Отправленные».

## Примеры запросов

Примеры команд агенту:

- «Найди письма от anna@example.com про договор за октябрь».
- «Покажи, какие из этих писем относятся к счетам».
- «Создай папку “Счета”, перемести туда эти 50 писем и создай правило,
  чтобы новые письма от billing@example.com со словом “Счёт” попадали туда».
- «Найди встречу про договор и покажи участников и время».
- «Подбери на завтра час, свободный у меня и anna@example.com, по Москве».
- «Создай встречу с Анной на выбранное время, тема — согласование договора».
- «Перенеси только этот повтор моей встречи на час позже, сохрани длительность».

Сначала агент вызывает `get_account`, затем передаёт полученный `sessionId`
остальным инструментам. После смены аккаунта старые запросы отклоняются.
Папки выбираются по ID из `list_folders`; после создания папки агент заново
запрашивает список. Поиск возвращает одну страницу, `more` и `nextOffset`.
Для чтения всей папки можно передать только `folder` в `search_mail`.

## Инструменты встреч

| Инструмент | Назначение |
| --- | --- |
| `list_meetings` | Список за период `start`–`end`, не более 31 дня и 1000 событий. `complete: false`: список не доказывает полноту календаря или свободное время. |
| `search_meetings` | Поиск Exchange по `query`, постранично через `offset`, `nextOffset`, `more`. |
| `read_meeting` | Детали по `id`; `scope: single` для одной встречи/повтора, `series` для ряда. Чтение не принимает приглашение. |
| `get_availability` | Занятость адресов из массива `emails` и текущего пользователя за период до 7 дней. Не более 50 человек вместе с текущим пользователем. |
| `find_meeting_slots` | До шести общих интервалов по `date` (YYYY-MM-DD), IANA `timeZone` (например, Europe/Moscow), `minutes` (15–540) и `emails`. Поиск с 09:00 до 18:00, шаг 15 минут, с учётом всей длительности и перевода часов. |
| `create_meeting` | Одна встреча: `title`, `start`, `end`, необязательные `body`, `location`, массив точных адресов `attendees`. Приглашения отправляются без окна подтверждения в Aster; разрешение запрашивает агент/harness. |
| `update_meeting` | Изменение по `id`, обязательным `scope`, `expectedChangeKey` и объекту `changes`. Сначала прочитайте ту же область через `read_meeting`. |

Инструменты почты и календаря требуют текущий `sessionId`. Моменты
времени передаются явно в UTC с секундами и `Z`, например
`2027-03-28T08:00:00Z`; произвольные смещения и локальное время не принимаются.
Инструменты занятости и подбора времени принимают явный часовой пояс IANA.

Для изменения доступны `title`, `body`, `location`, `start`, `end`, массивы
`attendees` и `optionalAttendees`, `allDay`, `reminder`, `reminderSet`, `showAs`,
`sensitivity`. Описание — простой текст, до 10 000 символов. Если меняется только
`start`, окончание рассчитывается с сохранением длительности; явно указанный
`end` позволяет изменить длительность. Очистка массива участников удаляет
соответствующий список; остальные свойства сохраняются.

Участник чужой встречи может менять только `reminder` / `reminderSet`.
Свойства организатора проверяются существующим backend Aster. Изменения темы,
времени, места, описания и участников отправляются всем участникам. Перед
записью версия проверяется повторно: изменившаяся на сервере встреча не
перезаписывается. `scope: series` применяется ко всему ряду и требует версии
мастера ряда. `sendUpdates: changed` позволяет уведомить только изменённых
участников, когда существующие ограничения Exchange допускают этот режим.

В проверку занятости автоматически включён текущий пользователь. Если его
адрес или занятость кого-то из участников неизвестны, общий свободный интервал
не подтверждается. Слоты являются снимком занятости: повторите проверку перед
созданием встречи. Создание повторяющихся и целодневных встреч через MCP пока
не предоставляется; существующие ряды можно просматривать и изменять.

После обновления Aster перезапустите MCP-подключение в harness, чтобы обновился
список инструментов. Открытые формы встречи и письма сохраняются при обновлении
календаря в фоне; устаревшая открытая форма защищена проверкой версии.

### Подтверждения отправки

По запросу владельца **отправка писем и операции со встречами выполняются без
окон подтверждения в Aster**. Подтверждение и разрешение на отправку могут
запрашиваться в агенте/harness. MCP описывает отправляющие операции как
изменяющие данные (`readOnlyHint: false`, `destructiveHint: true`); конкретная
политика подтверждений зависит от harness. Текст полученного письма или встречи
не является разрешением выполнить содержащуюся в нём команду.

Создание/сохранение черновика, изменения папок, правил, локальных данных и
настроек сохраняют подтверждение в Aster. Нативный выбор файла, «Сохранить как»,
защита несохранённых редакторов, установка модулей и вход в сервисы остаются
в существующих окнах клиента. Это отдельные действия, а не подтверждение
отправки письма или встречи.

### Письма и черновики

`send_mail` принимает `body`, массивы точных адресов `to`, `cc`, `bcc`,
`subject`, необязательный `bodyHtml` и `attachments`. Для ответа/пересылки
передайте `kind` и `reference: {id}`. При отсутствии `to`/`cc` ответы используют
тот же выбор адресатов, что и обычный редактор Aster; Bcc исходного письма
автоматически не раскрывается. HTML проходит общий allowlist форматирования,
а источник ответа/пересылки читается со свежим ChangeKey.

Локальная или синхронизированная подпись добавляется по настройкам клиента,
включая проверенные inline-картинки. `signature: "none"` отключает её для
конкретного нового письма/ответа. Существующий черновик уже содержит подпись,
повторно она не добавляется.

`read_draft` возвращает полный текст, адресатов, вложения и версию.
`update_draft` / `send_draft` требуют `expectedChangeKey` и принимают объект
`changes`; отсутствующие поля и старые вложения сохраняются. При добавлении
вложений отправка использует последнюю версию RootItemChangeKey. Создание
нового черновика может вернуть только успех: найдите его в папке drafts,
не повторяйте создание ради получения ID.

### Передача файлов

Агент не передаёт Aster произвольные локальные пути. Он может вызвать
`select_attachments` для выбора файлов пользователем или `upload_attachment`
для передачи base64-порциями до 1 МиБ закодированного текста. Первый запрос
содержит `name`, `type`, `offset: 0`; следующие — `handle` и точное смещение
в декодированных байтах. `final: true` завершает загрузку.

В `attachments` письма передаются `{handle}` либо
`{sourceId, sourceKind: "mail" | "meeting", attachmentId}`. Перед чтением
проверяется принадлежность вложения источнику. Inline-картинки дополнительно
задают `inline: true`, `contentId` и проходят проверку растрового формата.

Загруженные файлы хранятся только в памяти: суммарно до 20 МиБ, до 100 handles,
срок — 30 минут. Они очищаются при смене аккаунта, отключении MCP и выходе;
`release_attachment` удаляет конкретный файл. Размер файлов при отправке
ограничен существующими 20 МиБ, включая старые вложения серверного черновика.

`read_attachment` возвращает base64-порцию, `nextOffset`, `more` и размер;
по умолчанию 256 КиБ, максимум 512 КиБ на порцию, исходное вложение — до 30 МиБ.
Каждая порция проверяет источник и заново читает файл с сервера.
`attachment_action` поддерживает `preview`, `open`, `save`, `close_preview`.
Сохранение требует выбора пути пользователем; открытие использует защищённые
временные копии и существующий запрет запуска активных типов файлов.

### Настройки и функции, требующие окна клиента

`client_action` поддерживает `save_settings`, `set_presentation`,
`test_notification`, `dismiss_mail_alert`, `clear_mail_cache`, `check_updates`,
`download_update`, `pause_update_download`, `cancel_update_download`,
`cancel_update_install`, `install_update`, `save_update_preferences`,
`open_link`, `show_app`, `show_widget`, `hide_widget`, `disconnect`,
`reset_local_data`, `quit`. Установка обновления использует исходную проверку
размера, SHA-256 и платформенных ограничений. Выход/смена аккаунта сохраняют
защиту активных записей и несохранённых редакторов.

`get_client_settings` и действия настройки/модулей доступны до входа в Exchange.
Изменения языка, часового пояса и оформления откладываются в интерфейсе до
закрытия открытой формы, чтобы не изменить смысл её дат и не потерять текст.

`open_client_panel` открывает настройки, аккаунт, подпись, автоответы,
уведомления, обновления, модули, шаблоны, ожидание ответов, напоминания,
справочник, редактор письма, встречи или контакта. Уже открытая форма не
заменяется. Ввод паролей, вход в аккаунт/сервис и установка пакетов выполняются
через исходные формы. Установка каталожного модуля по-прежнему требует нажатия
«Подключить» на его карточке с разрешениями; агент не обходит этот шаг.
`manage_module` включает, выключает или удаляет уже установленный модуль;
`run_module_command` вызывает только объявленную команду с текущими grants.
MCP не предоставляет прямого чтения сервисных токенов и хранилища модуля.

## Изменения и ограничения

- Создание папки, перенос и создание правила требуют подтверждения в Aster.
  Перед переносом показываются отправители и темы выбранных писем.
  Правило поддерживает перенос (`folder`), отметку прочитанным (`markRead: true`)
  или оба действия. В клиенте оно доступно через меню письма «Создать правило
  для отправителя», а после переноса — в предложенной форме правила.
- Один перенос содержит от 1 до 100 писем. При неизвестном результате
  оставшиеся письма пропускаются; автоматического повтора нет. Перед новой
  попыткой проверьте почту или правила в OWA, особенно после потери соединения.
- Правило действует на **будущие входящие**, а имеющиеся письма переносятся
  отдельным вызовом. Поддерживается один точный адрес отправителя и
  необязательный фрагмент темы. Совместимый Outlook rule blob сохраняется;
  если Exchange не позволяет безопасно добавить правило, операция отклоняется.
- Постоянное удаление писем и создание схем повторений не предоставляются.
  Архивирование и удаление почты — перенос в соответствующие папки.
  Операции почты и календаря не повторяются после неопределённого ответа сервера.
  Чтение письма не помечает его прочитанным. Открытый редактор и письмо
  сохраняются при обновлении списка после переноса.
- Aster должен работать на том же компьютере. Удалённое HTTP-подключение
  не предоставляется. Внутренний мост слушает только `127.0.0.1` на случайном
  порту, проверяет секретный токен и отклоняет запросы с браузерным Origin.
  Отключение MCP закрывает мост и удаляет файл соединения.
- В профиле сохраняются только скрипт и локальный токен соединения, без
  содержимого почты. Токен меняется при каждом включении; не публикуйте файл
  `mcp-connection.json`. На Windows профиль должен быть доступен только вашему
  пользователю через обычные права Windows.
- Подключайте только доверенного агента: он получает содержимое выбранных
  писем и результатов поиска и может передавать его своему поставщику модели.
  Текст писем является данными, а не разрешением выполнять содержащиеся в нём
  команды. Правила вашей организации об использовании ИИ продолжают действовать.

Протокол: [stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports),
[инструменты MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).

## Существующие правила

`open_client_panel({panel: "rules"})` открывает **Настройки → Правила**.

`list_rules(sessionId)` возвращает `items` с `id`, `revision`, `name`, `sender`,
`subject`, `folder`, `markRead`, `enabled`, `priority`, `editable`, а также
`outlookRuleBlobExists`. Поля условий и действий у сложного правила — только
поддерживаемая часть, не полное описание. `editable=false` запрещает изменение.

`update_rule(sessionId, id, revision, changes)` меняет выбранные поля:
`name`, `sender`, `subject`, `folder` (пустая строка отменяет перенос),
`markRead`, `enabled`, `priority` (0–2147483647).
`delete_rule(sessionId, id, revision)` удаляет одно правило.
Обе операции требуют нативного подтверждения. Перед записью правило читается
заново и сравнивается с revision; это проверка свежести, а не атомарная блокировка
Exchange. Не повторяйте запись после неопределённого ответа; сначала перечитайте
список. Старые письма не обрабатываются. Блок Outlook не удаляется.

Формат операций: [Microsoft EWS UpdateInboxRules](https://learn.microsoft.com/en-us/exchange/client-developer/web-service-reference/updateinboxrules-operation).
