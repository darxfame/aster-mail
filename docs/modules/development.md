# Разработка и внедрение модулей

Контракт API 1 описан в [architecture.md](architecture.md); схема — [module.schema.json](module.schema.json). Рабочий пример — `examples/modules/sandbox-demo`. Он демонстрирует собственную логику, кнопки, внутренние команды, встраиваемую панель, зашифрованное состояние и события. Внешние сервисы не вызываются.

## Состав пакета

```text
module.json
main.js
panel.html
panel.js
panel.css
```

`files` перечисляет точные относительные пути всех ресурсов, кроме автоматически включаемого `module.json`. Список используется одинаково при установке из папки и GitHub; остальные файлы репозитория не загружаются и не исполняются. Включайте необходимые LICENSE/NOTICE.

`main.js` — браузерный ES module. Не CommonJS и не Node.js. Сборщик проекта модуля может собрать браузерные зависимости в локальные JS/CSS-файлы; сам Aster сборщик не требует. Не используйте удалённые CDN, inline script, inline event handlers, `eval`, workers, iframe или нативные зависимости.

`module.json`:

```json
{
  "apiVersion": 1,
  "id": "company.meetings",
  "version": "1.0.0",
  "type": "hybrid",
  "name": "Company meetings",
  "main": "main.js",
  "files": ["main.js", "panel.html", "panel.js", "panel.css"],
  "permissions": ["ui", "storage", "network", "meeting.draft"],
  "networkOrigins": ["https://meetings.example.com"],
  "networkHeaders": ["x-api-key"],
  "commands": [
    { "id": "create", "title": "Create meeting link", "slot": "meeting.create" },
    { "id": "configure", "title": "Configure", "slot": "internal" }
  ],
  "views": [
    { "id": "settings", "title": "Company meetings settings", "file": "panel.html", "slot": "panel", "height": 240 }
  ]
}
```

Адрес выше вымышленный. Это пример контракта, не реализация ktalk.ru. Нельзя добавлять ключи/пароли в пакет. Origin должен быть HTTPS без пути, query, userinfo и fragment; без wildcard. Имена `x-*` заголовков авторизации объявляются заранее. Cookie/Host/Origin/Referer и перенос учётных данных Exchange запрещены.

JSON Schema помогает редактору, а `node scripts/check-module.cjs <folder>` выполняет авторитетную проверку host, проверяет пути/ресурсы и рассчитывает digest без выполнения кода. Команды и представления имеют уникальные ID внутри пакета. Неизвестные поля, типы, разрешения и версии API отклоняются.

## API логики

```js
export async function activate(api) {
  const unsubscribe = api.onEvent(event => {
    // React only to the documented topics needed by this module.
  });
  return {
    commands: {
      async create(input, context) {
        const draft = await api.call('meeting.getDraft');
        // Validate the snapshot and obtain explicit user intent before remote writes.
        // Use the module's own view for service-specific forms.
        return { ready: Boolean(draft.start && draft.end) };
      },
      async configure() {
        return api.call('ui.openView', { view: 'settings' });
      }
    }
  };
}
```

`activate` вызывается один раз на экземпляр. Храните текущее состояние в памяти; необходимые настройки сохраняйте по мере изменения через `storage.set`. На остановку нельзя рассчитывать как на гарантированный callback: процесс может завершиться аварийно. Отключение от событий (`unsubscribe`) используйте при пересоздании подписок. Не рассчитывайте на `beforeunload` и не задерживайте остановку модуля: важные изменения собственной формы сохраняйте по мере ввода в зашифрованное состояние host. Все побочные эффекты `activate` ограничивайте и не создавайте внешние объекты автоматически.

Команды возвращают JSON-значение или `undefined`. Одновременно выполняется одна команда на экземпляр. Обрабатывайте ошибки сами; необработанная ошибка возвращается в Aster как ошибка модуля. Автоматического повтора нет. Ошибки SDK имеют `code`: `permission-denied`, `rate-limit`, `network-unknown`, `http-error` или `module-request-rejected`. Для HTTP возвращается безопасный `status`, без тела ошибки сервиса и без stack host. HTTP 500 и неопределённый сетевой результат нельзя считать доказательством, что внешняя запись не произошла.

| `api.call(method, input)` | Право | Контракт |
| --- | --- | --- |
| `ui.context`, `{}` | `ui` | Язык, тема, IANA timezone и масштаб интерфейса; без данных аккаунта |
| `ui.openView`, `{view}` | `ui` | Только объявленное представление своего пакета, во время пользовательской команды |
| `storage.get`, `{}` | `storage` | JSON-состояние ТОЛЬКО своего модуля и текущего аккаунта |
| `storage.set`, `value` | `storage` | Заменить всё своё JSON-состояние, до 16 КБ. Зашифрованное хранение host |
| `network.request`, `{url, method?, body?, bearer?, headers?}` | `network` | HTTPS origin из manifest, методы GET/POST/PUT/PATCH/DELETE; JSON-ответ до 64 КиБ. Custom headers только объявленные `x-*`; optional Bearer задаёт Authorization |
| `calendar.list`, `{start,end}` | `calendar.read` | UTC instants, основной календарь, до 31 дня, ответ `{items,truncated,complete:false}`; до 200 элементов `{id,title,start,end,allDay}`. Полнота не подтверждается этим API |
| `meeting.getDraft`, `{}` | `meeting.draft` | Snapshot открытой новой встречи в контексте команды. `{title,location,body,timeZone,start,end,truncated}`; UTC или `null` при неполном вводе |
| `meeting.openDraft`, `patch` | `meeting.draft` | Открыть новую встречу с предложенными полями; только во время команды |
| `meeting.patchDraft`, `patch` | `meeting.draft` | Предложить изменения актуальному editorId из контекста. Не редактирует сохранённые события |
| `events.publish`, `{topic,data}` | `events` | Host добавит `<module-id>.` к теме; только JSON |

`patch` допускает только `title`, `location`, `body`, `start`, `end`. Время — UTC ISO c `Z`; host переводит его в выбранный пояс. Адреса участников и отправка приглашений недоступны. Замена уже заполненных полей требует подтверждения пользователя в UI. Черновик может измениться после snapshot: модуль должен считать snapshot подсказкой, а пользователь проверяет итог перед отдельным нажатием отправки.

Сетевой посредник не использует accountSession, не отвечает на NTLM/proxy challenges, не следует redirect, не принимает cookies и не повторяет операции. При тайм-ауте, отмене или непонятном ответе результат может быть неизвестен: нельзя автоматически создавать вторую комнату. Сохраняйте полученный идентификатор сервиса и позволяйте пользователю проверить первый результат. Внешний объект может остаться созданным после закрытия редактора — это не означает, что можно отправить приглашение или удалять объект без отдельного разрешения.

Для API-ключа сделайте собственное поле `type="password"`, передавайте его только в `storage.set`, не возвращайте его в результаты команд и не выводите в console/UI. При отзыве ключа пользователь должен иметь возможность очистить своё состояние. Разрешение network вместе с другими разрешениями даёт возможность отправить доступные модулю данные объявленному сервису; используйте минимальный набор прав.

## API представления

HTML загружает свои стили и JavaScript относительными URL:

```html
<link rel="stylesheet" href="panel.css">
<button id="save">Save</button>
<output id="status" aria-live="polite"></output>
<script src="panel.js"></script>
```

В JS доступен только узкий мост:

```js
const value = await window.asterModule.command('configure', { example: true });
const settings = await window.asterModule.call('storage.get');
const unsubscribe = window.asterModule.onEvent(event => {
  document.querySelector('#status').textContent = event.topic;
});
```

Команды объявляются в manifest, включая `slot: "internal"`. Для операций над черновиком и открытия панелей вызывайте команду: она задаёт ограниченный контекст пользовательского действия. Прямой SDK-вызов из UI не создаёт такой контекст. Доступ к `window.aster`, DOM основного приложения, Electron, Node, файлам, cookies Exchange и произвольной сети отсутствует.

Собственные настройки и рабочие панели могут быть несколькими `views`. Для внедрения части в форму новой встречи укажите `slot: "meeting.create"`. Host управляет clipping и масштабом; не делайте окна фиксированного desktop-размера, используйте адаптивные CSS, доступные подписи, клавиатуру и явное состояние ошибок. Не маскируйтесь под системные подтверждения Aster.

## Правила внедрения

1. Зафиксировать сценарий, данные, внешние записи и их неопределённые результаты. Проверить, что существующий SDK покрывает сценарий; не менять основные алгоритмы Exchange ради одного сервиса.
2. Определить минимальные разрешения и точные origins/headers. Сначала согласовать изменение API host, если текущего контракта недостаточно.
3. Разработать пакет отдельно; проверить лицензии зависимостей, отсутствие секретов и удалённых CDN.
4. Проверить `check-module.cjs`, подготовить fingerprint и release notes пакета. При изменении ресурсов повышать версию; не подменять опубликованный пакет.
5. В отдельном тестовом аккаунте установить пакет, выдать разрешения и проверить формы/команды без реальной отправки писем.
6. Проверить HTTP 401/403/429/500, redirect, timeout, обрыв после внешней записи, ошибку JSON, отзыв токена и отмену пользовательского действия. Повторов записи быть не должно.
7. Проверить чужой аккаунт, stale editorId, отключение/выход во время запроса, изменение файлов, неправильный manifest, невыданные разрешения и крупные IPC-сообщения.
8. Проверить адаптивность 100/150/200%, клавиатуру, прокрутку/clipping, несколько панелей и восстановление собственного состояния после закрытия панели. Повторно проверить обычное подключение, календарь и редакторы без модулей.
9. Выполнить `npm run check`, `npm test`, `npm run test:connection`, `npm run test:modules`. Изменения в коде host требуют независимого review и приёмки Windows/macOS до production.
10. Развёртывать без фоновой установки/включения. Для ручного импорта включение отдельно; для одобренного каталога явное нажатие «Подключить» одновременно выдаёт показанные права. Обновление — явное удаление/подключение новой версии и повторная выдача прав. При rollback отключить пакет, сохранить/экспортировать нужные собственные настройки безопасным способом и вернуть известный digest. Скрытых автоматических обновлений/миграций в API 1 нет.

## Границы первой версии

Нет магазина, доверенных подписей издателей, Node.js, нативных расширений, workers, произвольных iframe, WebRTC, общих account cookies, доступа к почте, фоновой отправки или изменения сохранённых встреч. Cookie-only SSO, OAuth authorization-code flow, бинарные сетевые ответы, webhooks и новые extension points требуют отдельного контракта и проверки. Общий browser-token вход описан ниже. Это ограничения host API, а не обещание автоматически поддержать любой внешний сервис.

## Модули автора и предложения сообщества

[Aster Mail Modules](https://github.com/darxfame/aster-mail-modules) — источник
модулей от автора Aster Mail и репозиторий для предложений собственных модулей.
Идею можно предложить в Issues, готовый пакет — через Pull Request. При подготовке
пакета соблюдайте контракт API 1 и правила внедрения выше; приложите описание
сценария, разрешений, внешних сервисов, лицензии и инструкцию проверки. Размещение
в этом репозитории не заменяет подтверждение установки и разрешений в Aster.

## Подключение непосредственно с GitHub

В «Настройки → Модули → Подключить с GitHub» укажите URL публичного репозитория, необязательный ref (ветка/тег/полный SHA) и относительную папку пакета. Например, учебный пакет Aster расположен в `examples/modules/sandbox-demo` ветки `codex/modules`.

Host разрешает ref в один полный commit SHA, затем загружает `module.json` и только перечисленные `files` через immutable raw URLs этого SHA. Суммарный предел — 10 МиБ; redirects, Git credentials, установочные hooks, npm install, сборка и git submodules не запускаются. Source repo, commit, directory и digest сохраняются как provenance вне манифеста и показываются перед установкой. Время загрузки ограничено двумя минутами, запросы отменяются при смене аккаунта. Файлы не выполняются до отдельного включения пакета и выдачи разрешений.

Прямое подключение не означает совместимость любого GitHub-проекта с Aster: репозиторий должен содержать module.json API 1 и готовые браузерные ресурсы. Private repos и GitHub Enterprise пока не поддерживаются; передача пароля Exchange, cookies или автоматическое использование Git credentials запрещены.

## Каталог одобренных модулей

«Настройки → Модули → Каталог одобренных модулей» читает `catalog.json` из основной
ветки `darxfame/aster-mail-modules`. Карточка показывает описание, версию,
разрешения, сетевые адреса и фиксированный источник пакета. «Подключить» одним
нажатием устанавливает и включает именно эту версию с перечисленными правами;
пакеты, подключённые вручную, сохраняют отдельное подтверждение разрешений.

Каталог публикует только автор репозитория после review. Формат —
`{catalogVersion:1,modules:[{manifest,description,commit,directory,digest}]}`.
`manifest` — полный проверенный manifest API 1; `commit` — SHA из 40 символов
коммита с готовым пакетом в этом же репозитории, `directory` — его папка,
`digest` — SHA-256 из `node scripts/check-module.cjs <folder>`. Пакет сначала
публикуется отдельным коммитом, затем его точный SHA и digest добавляются в каталог.
Пустой список означает отсутствие одобренных пакетов, а не ошибку загрузки.

Перед установкой клиент заново читает каталог. Если он изменился после открытия
списка, нужно обновить список и заново выбрать карточку. Несовпадение manifest или
digest, отзыв записи, смена аккаунта либо отмена блокируют установку. Чужие репозитории
и произвольный ref из renderer для этого пути не принимаются. Автообновлений нет.
Состояние «Уже подключён» блокирует повторную установку и не перезаписывает настройки.
Ошибки сети показываются внутри каталога, ранее подключённые модули продолжают работать.

Каталог содержит только метаданные. Реализации сервисов и ресурсы модулей находятся
в репозитории `aster-mail-modules`; код SDK в `aster-mail` остаётся общим.

## Общий SDK входа в сервис и открытия приложения встречи

Возможности описываются пакетом, без кода конкретного сервиса в Aster:

```json
{
  "permissions": ["network", "auth.session", "meeting.launch"],
  "networkOrigins": ["https://rooms.example.test"],
  "authentication": {
    "type": "browser-token",
    "origins": ["https://rooms.example.test"],
    "identityOrigins": ["https://identity.example.test"],
    "path": "/login",
    "capture": {
      "storage": "localStorage",
      "key": "service-login",
      "tokenPath": ["credential", "access"],
      "expiresAtPath": ["credential", "until"],
      "rejectPath": ["anonymous"]
    },
    "authorization": { "scheme": "Bearer" }
  },
  "meetingLinks": {
    "scheme": "fictional-meeting-app",
    "origins": ["https://rooms.example.test"]
  }
}
```

Это фрагмент манифеста, остальные обязательные поля API 1 остаются необходимыми.
С `auth.session` доступны `auth.signIn({origin})`, `auth.status({})`,
`auth.signOut({})`. Вход и выход требуют пользовательской команды. Вход открывает
отдельную непостоянную sandbox-session без preload/IPC Aster, cookies Exchange и
доступа к аккаунту. HTTPS-навигация ограничена `origins`/`identityOrigins`.
Ресурсы HTTPS страницы входа могут загружаться с CDN сервиса; разрешение входа
не даёт модулю прямую сеть в его собственных runtime/UI.

Host читает только объявленный JSON-ключ `localStorage` или `sessionStorage` на
точном origin выбранного сервиса. Разрешены пути к полям, а не исполняемые
скрипты/селекторы произвольного кода. Истинное значение `rejectPath` отклоняет
сессию; `expiresAtPath` должен содержать время, разбираемое как ISO instant.
Ключ может хранить до 16 КБ JSON, токен — до 4096 символов. Host сохраняет токен
в зашифрованном хранилище своего модуля; статус возвращает только факт входа,
origin/срок/состояние окна. Очистка входа удаляет токен и закрывает окно; остановка
модуля, выход из аккаунта и тайм-аут закрывают окна и очищают временную session.
Сохранённый токен остаётся в зашифрованных настройках до явного выхода из сервиса
или удаления настроек аккаунта/модуля. Время входа ограничено пятью минутами.

`network.request({url,auth:'session'})` добавляет объявленную схему Authorization
(например `Bearer` или `Session`) только на origin, к которому относится токен.
Его нельзя смешивать с `bearer`/собственными headers. Токен не выдаётся SDK напрямую;
сетевой сервис всё равно получает его и может возвращать собственные данные в
ответе. Нет автоматического refresh, повторов записи или перехвата пароля.
Cookie-only SSO и OAuth с обменом authorization code не поддерживаются этим
адаптером и потребуют отдельного общего контракта. Реальную совместимость входа
каждого провайдера проверяют в его репозитории.

`meeting.launch` описывает преобразование HTTPS-ссылки в зарегистрированный
протокол приложения с тем же host/path/query. Разрешены точные origins и простые
сегменты пути; executable paths, аргументы команд, script/file/system URI и
произвольный шаблон URL не принимаются. При пользовательском подключении к встрече
host проверяет установленный обработчик и показывает приложение и целевую ссылку.
Отмена ничего не запускает; при ошибке нет скрытого повторного открытия в браузере.
Если подходят несколько модулей, нужно отключить лишний маршрут. Без подходящего
модуля сохраняется обычное открытие HTTPS. Сам модуль не получает `shell` и не
может запускать приложение фоновым RPC.

См. [Electron isolated worlds](https://www.electronjs.org/docs/latest/api/web-contents#contentsexecutejavascriptinisolatedworldworldid-scripts-usergesture)
и [Electron external URLs](https://www.electronjs.org/docs/latest/api/shell#shellopenexternalurl-options).
Нативная проверка общего контракта: `npm run test:module-sdk` использует вымышленные
HTTPS origins и токены без реального внешнего сервиса или запуска приложения.

Просмотр публичного каталога в настольном клиенте доступен до подключения Exchange
и в деморежиме. Он использует отдельную session и не читает настройки аккаунта.
Установка/включение остаются привязаны к реальному аккаунту; без входа карточки
показываются с недоступной кнопкой подключения.

## Дополнительные серверы по выбору пользователя

Модуль может объявить `optionalOrigins: [{domain:"example.test",includeSubdomains:true}]`
вместе с правом `network`. Это семейство возможных серверов, а не разрешение
отправлять запросы на все его адреса. Во время пользовательской команды
`network.requestOrigin({origin:"https://diy.example.test"})` показывает нативное
подтверждение точного origin и возможностей модуля. Отмена возвращает
`{granted:false,origin}` без изменения доступа. Повторный запрос уже разрешённого
origin возвращает `{granted:true,origin}` без нового диалога.

До согласия network/auth/meeting routing не используют этот адрес. После согласия
host добавляет точный origin к сетевому посреднику, сервисным origins входа и
декларативному маршруту встречи. IdP origins не расширяются. Токен другого origin
по-прежнему не переносится. До восьми дополнительных HTTPS origins сохраняются в
зашифрованных настройках модуля текущего аккаунта. Модуль не должен менять сервер
или ключ, если пользователь отменил разрешение. Удаление модуля удаляет grants.
Порты, пути, userinfo, маски и соседние домены не принимаются вместо точного origin.

Для публикации требуется feature `network.origin-grants`. Семейства доменов,
формат токена и протокол приложения принадлежат manifest пакета. В host нет
проверок по имени провайдера.

Каталог поддерживает также опубликованный индекс `schemaVersion:1` с полями
`id/name/version/source/sha256/permissions/networkOrigins/networkHeaders/host` и
необязательными `authentication`, `meetingLinks`, `optionalOrigins`. Клиент читает
manifest по полному commit и сверяет объявленные возможности до показа кнопки
подключения; перед установкой перепроверяет весь пакет. Несовместимые версии
видны в списке с недоступной кнопкой, не прячутся и не исполняются.

Типизированные ошибки SDK собираются в мире самого модуля из безопасного envelope
моста. `code`/HTTP `status` сохраняются и при настоящем Electron contextBridge.

## Обновление и миграции настроек

В каталоге новая версия установленного ID показывает «Обновить с сохранением
настроек». Пакет заново загружается по immutable commit и проверяется. Удаление
перед обновлением не требуется. Сохраняются `data`, включённость, совместимая
сервисная сессия и точные origin grants; данные разных аккаунтов не смешиваются.
Расширение возможностей или смена источника требуют отдельного подтверждения.
Несовместимая схема сессии не переносит токен в новый способ авторизации.

Версия данных задаётся независимо от версии пакета: `settingsVersion` (по умолчанию
1). Если схема не меняется, настройки сохраняются целиком, включая API-ключи и
неопределённые результаты внешних записей. Например:

```json
{
  "settingsVersion": 2,
  "settingsMigrations": [{
    "from": 1,
    "to": 2,
    "operations": [
      {"op":"rename","from":["apiKey"],"path":["credentials","token"]},
      {"op":"setDefault","path":["appearance","theme"],"value":"light"}
    ]
  }]
}
```

Первый контракт поддерживает последовательные шаги `n → n+1`, переименование
JSON-полей без перезаписи существующего назначения и установку отсутствующих
значений. Удалений и произвольного исполнения кода в main нет. Пути работают с
объектами, не индексами массивов; целые массивы можно переносить как значения.
Для сложного преобразования, не покрытого контрактом, сначала расширяется SDK
с тестами. Нельзя молча очистить настройки или заменить отсутствующую миграцию
инициализацией. Новый пакет при первой установке инициализирует пустые настройки
своим обычным кодом; миграции применяются к ранее сохранённым данным.

Миграция выполняется на копии данных, в порядке схем, без сети и до переключения
версии. Нет шага, конфликт ключей, неизвестная операция, превышение 16 КБ или
ошибка шифрованного сохранения — старая запись остаётся. Финальные версия пакета,
схема и настройки записываются вместе через атомарный LocalStore. Во время
операции нельзя запускать/удалять/переключать модуль; активные команды и окно входа
нужно сначала завершить. После обновления runtime запускается заново; SDK не
повторяет создание комнат и не отправляет приглашения.

Автоматических обновлений нет. Старые package snapshots пока сохраняются на диске;
они не исполняются без текущей записи аккаунта. История settings-backup и ручной
rollback с понижением схемы — следующие отдельные возможности, не автоматический
откат после произвольного server write. При проблеме уже активированной версии
публикуется исправление с новой версией пакета и проверенным преобразованием схемы.
