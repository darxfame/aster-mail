# Проверка Aster Mail 0.2.0

База сравнения — Aster Mail 0.1.33, commit
`ae25b4044052b7ab73530cb9d36d09ac5559a048`.

## Регрессии на macOS Apple Silicon

- Синтаксические проверки и Node: 343 успешно, одна проверка Windows NTFS
  пропущена на macOS. Проверены существующие сценарии почты, календаря,
  вложений, уведомлений, обновлений и отдельных окон редактора.
- Настоящий Electron: form login, gzip и первое чтение OWA на вымышленном
  loopback-сервере. Реальные почтовые учётные данные не используются.
- Настоящий sandbox модулей: запрет Node/file/direct network, account-scoped
  состояние, изолированные представления, отмена при смене аккаунта.
- Общий SDK: изолированный вход, декларативный захват токена, отсутствие секрета
  в каталоге и ответах, сохранение HTTP code/status через contextBridge.
- Обновления модулей: сохранение данных и неопределённых записей, миграции,
  отказ при конфликте и ошибке сохранения, подтверждение новых прав,
  восстановление настроек устаревшего пакета без исполнения его кода и отказ
  при повреждённой копии новой версии.

## Интерфейс

`scripts/test-release-ui.cjs` сравнивает исходный renderer и кандидат в настоящем
Electron. Масштаб задаётся через desktop zoom, с действующими media queries.
Проверены 100/150/200% и светлая/тёмная темы.

Геометрия почты, календаря, контактов, редактора и полей новой встречи совпадает
с базой при отключённых модулях. Обновление списка сохраняет тот же открытый
редактор, тему и текст черновика. Открытие карточки встречи не меняет участие.
Дополнительно проверено, что меню включённого модуля помещается в toolbar,
а его часть формы не вызывает горизонтального переполнения.

Устранён сдвиг полей новой встречи из-за пустого контейнера модулей.

## Проверка собранного приложения

Для проверки кода внутри app.asar нативные сценарии поддерживают
`ASTER_PACKAGED_APP=/path/to/app.asar`. UI-сравнение поддерживает
`ASTER_UI_BASELINE` и `ASTER_UI_CANDIDATE`, включая renderer в app.asar.
Это позволяет проверить сборку отдельно от исходной рабочей копии.

Сборка выполняется из самостоятельного `npm ci` по lock-файлу: symlink на
node_modules другой рабочей копии не используется для установщика.
Проверяются версия, ресурсы SDK, наличие зависимостей XML-парсера, подпись macOS
и повторная установка пакета из настоящего GitHub-каталога в вымышленный аккаунт.
Установка пакета в fixture не запускает реальные вход, встречи или отправку.

## CI и пределы проверки

Проверки Node и нативные connection/sandbox/SDK-сценарии включены в CI
и выпуск установщиков на macOS и Windows. Проверка Windows NTFS выполняется
на Windows runner. Результаты конкретного запуска доступны в GitHub Actions.

Реальный корпоративный OWA/SSO, отправка писем/приглашений и визуальная приёмка
Windows не проверялись этими fixture. Совпадение геометрии и пройденные тесты
не являются гарантией совместимости с любой конфигурацией сервера.
