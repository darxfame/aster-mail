# Подпись и Keychain macOS

[← Разработка](../CONTRIBUTING.md) · [О проекте](../README.md)

Команды выполняются из корня репозитория.

Один раз выполните `npm run setup:mac-signing` на Mac. Команда создаёт
сертификат `Aster Mail Local Signing` на 10 лет и импортирует его с закрытым
ключом в пользовательскую связку `login`. Доступ к ключу предоставляется
`/usr/bin/codesign`; доверие сертификату ограничено подписью кода для текущего
пользователя и не распространяется на HTTPS. macOS может запросить подтверждение.
Временные файлы ключа удаляются после импорта. Повторный запуск использует тот же
сертификат; отсутствие его закрытого ключа требует восстановления, а не замены.

`npm run pack:mac` и `npm run dist:mac` используют этот сертификат. При отсутствии
сертификата сборка завершается ошибкой; автоматического перехода на ad hoc нет.
Для сборки на другом Mac или в CI нужно импортировать тот же сертификат **с тем же
закрытым ключом** из защищённого паролем `.p12`, разрешить подпись через `codesign`
и установить доверие только для подписи кода. Не загружайте ключ в репозиторий.
GitHub Actions получает защищённый паролем `.p12` из репозиторных Secrets
`MAC_SIGNING_CERTIFICATE` (Base64) и `MAC_SIGNING_PASSWORD`. Ключ импортируется
во временную связку runner, а отпечаток проверяется до сборки и в подписи
готового приложения. Связка и временные файлы удаляются завершающим шагом.
Эти Secrets доступны только сборкам релизных тегов и ручным запускам workflow,
а не проверкам pull request. Ручной запуск `Publish installers` создаёт артефакты
macOS и Windows без публикации релиза; push тега публикует их как раньше.

Сделайте резервный экспорт через «Связка ключей → Мои сертификаты →
Aster Mail Local Signing → Экспортировать» в `.p12` с отдельным паролем.
Один `.cer` не содержит закрытого ключа. Time Machine может сохранить связку,
если она включена в резервное копирование; отдельный `.p12` нужен для надёжного
переноса ключа на другой Mac. Самоподписанная подпись не заменяет Developer ID
и нотариализацию; предупреждения Gatekeeper при установке сохраняются.
Постоянная самоподписанная подпись позволяет проверить преемственность обновлений.
Ранее элемент `aster-mail Safe Storage` имел дополнительное ограничение по `cdhash`
основного приложения: смена сборки вызывала новый запрос Keychain даже с прежним
сертификатом. Теперь упакованный Mac-клиент использует неизменяемый помощник
`assets/keychain-macos/aster-keychain-v1`. Его хэш остаётся прежним между релизами,
поэтому обычное обновление Aster не меняет идентичность клиента Keychain.

Помощник хранит отдельный 256-битный ключ в Keychain и выполняет AES-GCM;
ключ не передаётся в Electron. Ввод/вывод ограничен закрытыми каналами родителя,
размером сообщений и операциями шифрования/расшифрования. Перед обращением к
Keychain проверяются подпись и подписанный маркер защищённого Aster; другие
приложения и старые Electron-сборки не допускаются. В выпускаемом Aster отключены
RunAsNode, NODE_OPTIONS и Node inspector, включены ASAR integrity и OnlyLoadAppFromAsar.
Точный cdhash Electron Framework дополнительно закреплён в подписанном Info.plist:
подмена старым Framework с тем же сертификатом не даёт доступ к Keychain.
Модули не получают нового IPC или доступа к помощнику.

Старые файлы переносятся через `safeStorage` атомарно, без открытых копий,
при первом восстановлении аккаунта; профиль модулей переносится независимо.
Старые версии Aster новый формат зашифрованных файлов не читают.
При этом один запрос старого Keychain ещё возможен. Отказ, повреждение или смена
сессии сохраняют исходный файл; неуспешная миграция не заменяется открытым хранением.
Если старое хранилище сообщает о недоступности, обращения к нему не повторяются
в том же процессе; повреждённый отдельный файл не блокирует остальные.
Блокировка/сброс самой связки ключей по-прежнему может требовать системного действия.

Исходник — `native/keychain-helper-v1.swift`, паспорт с SHA-256 бинарника и исходника —
`desktop/keychain-helper.json`. **Не пересобирайте и не переподписывайте v1 при выпуске.**
`npm run build:keychain-helper` — только явное первоначальное создание; существующий
бинарник не перезаписывается. Release-сборка копирует его без изменений и проверяет
хэш, подпись и Electron fuses после подписи приложения. Изменение помощника требует
отдельной версии и планируемого переноса ключа. Подпись не включает Touch ID и
не заменяет Developer ID/нотариализацию. В режиме разработки остаётся `safeStorage`.
