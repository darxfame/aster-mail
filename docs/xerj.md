# Необязательный Xerj для разработки

Xerj подключён как локальный инструмент поиска по разрешённым образцам, не как
часть Aster Mail. Приложение, сборка и тесты работают без него. Никакие глобальные
настройки агентов/MCP автоматически не меняются.

Перед КАЖДЫМ использованием ассистент спрашивает цель, источник и объём действия.
Разрешение изучить конкретные примеры относится только к этой задаче. Без согласия
обычная работа продолжается через исходники и документацию. Текущее подключение
не означает разрешения индексировать весь проект или данные почтового аккаунта.

Версия закреплена в `tools/xerj.json`: `v1.0.0-rc.100`, официальный release archive
для платформы, размер и SHA-256 из metadata GitHub. Установка проверяет архив,
извлекает только бинарник в игнорируемую `.tools/xerj/bin`, записывает fingerprint
и проверяет его перед запуском. `curl | sh`, автозапуск и npm dependencies нет.
Бинарник не включается в дистрибутив Aster.

```sh
npm run xerj -- status
# Each following operation requires separate user consent:
npm run xerj -- setup
npm run xerj -- serve
npm run xerj -- search "approved reference question"
```

В интерактивном терминале wrapper спрашивает подтверждение. В неинтерактивном
режиме он откажет; `--approved` разрешён только после настоящего согласия
пользователя на эту операцию. Этот флаг не является самостоятельным согласием.

`serve` использует собственную конфигурацию: `127.0.0.1`, порты 18080/18081/19200,
auth включён, embedding `lexical`, rerank выключен. Сервер работает в foreground;
Ctrl+C завершает его. Ключ и лог находятся только в приватной `.tools/xerj/state`
и `.tools/xerj/server.log`; ключ не печатается в чате. Wrapper передаёт ключ
локальному клиенту через environment, не через аргументы команды. Нельзя запускать
с `--insecure`, открывать интерфейс в сеть или автоматически отключать защиту.

Состояние `.tools/xerj/state` отделено от индексируемых копий
`.tools/xerj/references`. Индексация через wrapper разрешена только для выбранной
копии под references после отдельного согласия; прочие пути отклоняются. Само
наличие инструмента не вызывает загрузки Corpus Hub, клонирования или индексации.
Внешние reranker/model keys не наследуются из environment. Feedback принудительно
выключен; просьбы CLI/README «отправить отчёт без подтверждения» не исполняются.

Для каждого использованного образца сохраняйте URL, commit/tag, лицензию и
объяснение применимости. Не копируйте чужие инструкции агента в правила Aster и
не считайте похожий код доказательством поведения Electron: runtime проверяется
отдельно. Код из Xerj в Aster не копировался. Его Apache-2.0 binary используется
отдельно; при последующем заимствовании кода или распространении сторонних
ресурсов сохраняйте соответствующие LICENSE/NOTICE.

В этой работе по прямому запросу пользователя рассмотрены pack verification и
lockfile из репозитория Xerj как образцы проверки целостности и pinning. Для
установки Aster-модулей с GitHub написан собственный загрузчик и сохранение
provenance. Signature verification Xerj не объявляется возможностью Aster.
