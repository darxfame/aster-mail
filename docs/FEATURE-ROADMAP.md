# Развитие Aster Mail через HTTPS OWA

Обновлено 30 октября 2026 года. Этот план заменяет прежний план с обязательным EWS.
Целевая среда — корпоративный сервер с работающим браузерным OWA, к которому
Outlook и Apple Mail не подключаются. Новые этапы принимаются без зависимости от EWS.
[To-do по версиям и релизам](OWA-TODO.md).

HTTPS — транспорт. OWA и EWS — разные точки доступа: `/owa` и `/EWS/Exchange.asmx`.
Работа одной не доказывает доступность другой. Отказ настольного клиента может зависеть
от аутентификации, Autodiscover и политик. План не требует изменения сервера.
[Документация каталогов Exchange](https://learn.microsoft.com/en-us/exchange/plan-and-deploy/post-installation-tasks/configure-mail-flow-and-client-access).

## Возможности текущего клиента

| Направление | Уже через OWA JSON | Зависит от EWS или требует подтверждения |
| --- | --- | --- |
| Почта | Папки, списки, тело, read/unread, флаг, важность, перенос; массовые операции в 0.1.18 | Отправка, Reply/Reply All/Forward, сохранение и продолжение черновиков сейчас EWS |
| Папки | Дерево и счётчики | Создание, переименование, перенос папки в корзину и прочитать всю папку сейчас EWS |
| Редактор | Форматирование, цитата, выбор файлов, защита несохранённого текста | Запись/отправка, чтение файлов/CID и серверной подписи имеют зависимости от EWS |
| Поиск | ExecuteSearch/StartSearchSession, страницы, фильтры папки | Расширенные критерии, цепочки и категории требуют проверки OWA; правила сейчас EWS |
| Уведомления | Проверка OWA раз в 15 секунд, системный показ и дедупликация | Delta/streaming OWA не подтверждены; EWS Subscribe не является заменой |
| Автоматизация | Клиентские возможности | OOF и серверное расписание нельзя обещать по документации EWS |
| Календарь и люди | GetCalendarView, базовый GetItem, личные контакты без поиска, free/busy | Детали/создание/изменение/RSVP встреч, GAL ResolveNames, фото и создание контакта сейчас EWS |

Семантика EWS полезна для модели данных, но не подтверждает JSON-контракт OWA.
Наличие функции в браузере также не означает публичный стабильный API.
Не делать fallback EWS ↔ OWA после неизвестного результата записи: это повтор операции.

## Подтверждение нового контракта OWA

1. Зафиксировать версию сервера и пользовательский сценарий в браузерном OWA.
2. На согласованном тестовом ящике получить запрос/ответ. До сохранения fixture удалить
   cookies, CANARY, пароли, реальные адреса, ID и содержимое; не хранить необработанный HAR.
3. Проверить endpoint, типы, ошибки, ItemId/ChangeKey, истёкшую сессию и неизвестный результат.
   Бинарную/multipart загрузку нельзя заменять выдуманным JSON CreateAttachment.
4. Реализовать минимальный адаптер и injected-transport регрессии с вымышленными данными.
5. Проверить весь сценарий при запрете `/EWS/`. Mock-тесты не доказывают совместимость сервера.
6. Выпустить отдельную версию. Неподтверждённую возможность объяснить пользователю
   либо предложить выполнить в браузерном OWA.

Не выполнять отправки и приглашения в основной почте для определения возможностей.

## Первый этап 0.1.18

Бизнес-ценность — разобрать накопившиеся входящие пачками, не открывая каждое письмо.
До 100 загруженных писем выбираются мышью и клавиатурой. Read/unread и перенос в папку,
архив или корзину используют существующие OWA UpdateItem/MoveItem без EWS.
Выбор не отмечает письмо прочитанным и не означает весь ящик.

Первая ошибка останавливает остаток группы. Клиент показывает подтверждённые операции,
неподтверждённую и пропущенные. Автоматических повторов и постоянного удаления нет.
Выбор сбрасывается при смене области/аккаунта и после операции; открытый редактор сохраняется.
Версия включает накопленные исправления аудита, но не объявляется полностью свободной
от EWS: исходящий цикл и дополнительные возможности переносятся следующими этапами.

| 0.1.24 / v0.1.24 | Шаблоны и автоматизация | Шаблоны клиентские; OOF/расписание только при подтверждении сервера |
| 0.1.25 / v0.1.25 | Несколько аккаунтов и native-интеграции | Раздельные сессии и хранилища; системные API |

Будущие номера задают порядок, а не сроки. Условная функция не должна делать релиз
бесполезным при её недоступности: например, шаблоны не зависят от OOF.
Каждый этап: реализация → синтаксис/тесты → demo UI → локальная сборка → commit/tag →
CI macOS arm64 + Windows x64 → публикация обоих установщиков. Теги не перемещаются.
Если одна сборка не прошла, этап не считается выпущенным. Примечания описывают именно эту версию.

## Ограничения обещаний

Короткое Undo Send задерживает передачу команды, не отзывает доставленное письмо.
При закрытии во время задержки нужно явное поведение отмены/сохранения.
Расписание на часы/дни требует серверного механизма и испытания при закрытом Aster;
локальный таймер нельзя выдавать за серверную отложенную отправку.
Автоответ требует серверной настройки, а не цикла ответов клиента.

Первую страницу из 50 входящих со временем нужно заменить подтверждённым OWA-механизмом
изменений или ограниченным обходом пропущенных страниц. EWS delta/streaming из прежнего
плана не предполагается доступным. Транспорт для streaming нужен только после проверки API.

Полноценный офлайн потребует отдельного изменения запрета AGENTS.md сохранять payload.
Graph не считается автоматической заменой данного OWA-сервера. Регулярные рассылки,
административное делегирование и изменение корпоративной аутентификации не входят в перенос.

Критерий готовности: получить/найти/прочитать, ответить/переслать, приложить/скачать файл,
сохранить/продолжить черновик и обработать группу при заблокированном EWS; ясные состояния
сохранения/отправки. Затем календарь и каталог на целевом сервере. Установленные macOS
и Windows испытываются отдельно; сертификаты издателя не считаются функциональным дефектом.
